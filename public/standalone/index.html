React Advanced

Virtual DOM & Reconciliation: How does React diff trees and why are keys essential?

▼
React keeps an in-memory Virtual DOM tree. When state changes, the Fiber reconciler compares the new tree with the previous snapshot in O(n) heuristic time, batching minimal mutations to the real browser DOM.
Core Explanation:
  • Virtual DOM: Pure JS representation of UI. Manipulating JS objects is orders of magnitude faster than browser reflows and repaints.
  • Fiber Reconciler: Enables incremental rendering. Breaks work into interruptible units so smooth animations and typing take precedence over heavy computations.
  • Why Keys Matter: Keys give elements persistent identity. Using array index causes state bleed across inputs when items are deleted, filtered, or reordered.
keys-reconciliation.jsx 
// BAD: Index as key causes state bleed on deletion/reorder
function BadList({ items }) {
  return items.map((item, idx) => <input key={idx} defaultValue={item.text} />);
}

// GOOD: Unique stable IDs preserve element focus and state
function GoodList({ items }) {
  return items.map(item => <input key={item.id} defaultValue={item.text} />);
}
💡 Interview Tip: Explain that Fiber allows React to pause rendering to prioritize user events on the browser main thread.
React Intermediate

Hooks Deep Dive: useEffect vs. useLayoutEffect vs. useMemo vs. useCallback

▼
useEffect runs asynchronously after paint; useLayoutEffect runs synchronously before paint; useMemo caches computed values; useCallback caches function definitions.
  • useEffect: Non-blocking. Ideal for data fetching, event listeners, and timers.
  • useLayoutEffect: Synchronous before paint. Use only for measuring DOM geometry to prevent screen flickering.
  • useCallback(fn, deps): Prevents breaking referential equality on props passed to memoized children (React.memo).
hooks-usage.jsx 
// useMemo caches expensive calculations
const sortedUsers = useMemo(() => users.sort((a, b) => b.score - a.score), [users]);

// useCallback stabilizes function identity passed to child
const handleVote = useCallback((userId) => {
  castVote(userId);
}, []); // Re-used across all parent renders

Java Beginner

The Four Pillars of Object-Oriented Programming (OOP) in Java

▼
Encapsulation (data hiding), Abstraction (contract without details), Inheritance (code reuse with extends), and Polymorphism (runtime overriding & compile-time overloading).
  • Encapsulation: Private variables with verified accessors/mutators.
  • Abstraction: Defining contracts through interfaces and abstract classes.
  • Inheritance: Establishes "is-a" relationships while preventing duplicate code.
  • Polymorphism: One interface, multiple concrete behaviors at runtime.
OopDemo.java 
interface Notifier { void send(String msg); }

class EmailNotifier implements Notifier {
    @Override
    public void send(String msg) {
        System.out.println("Email sent: " + msg);
    }
}
Java Intermediate

JVM vs. JRE vs. JDK & Java Memory Architecture (Stack vs. Heap)

▼
JDK contains the compiler and tools; JRE provides runtime libraries; JVM executes bytecode. Stack is thread-private for primitive variables and method frames; Heap is shared for all allocated objects.
  • Stack: Fast LIFO allocation. Throws StackOverflowError on runaway recursion.
  • Heap: Managed by Garbage Collector. Throws OutOfMemoryError when allocation fails.

JS Beginner

var vs. let vs. const and the Temporal Dead Zone (TDZ)

▼
var is function-scoped and hoisted with undefined. let and const are block-scoped and hoisted into the Temporal Dead Zone until initialized.
tdz-example.js
console.log(x); // undefined (var)
var x = 5;

// console.log(y); // ReferenceError (TDZ)
let y = 10;
JS Advanced

Event Loop: Microtasks (Promises) vs. Macrotasks (Timers)

▼
Synchronous call stack executes first. When empty, all microtasks (.then, queueMicrotask) are drained before the next macrotask (setTimeout) runs.

Node.js Architecture: V8 Engine, Libuv, and Non-blocking I/O

▼

Express Middleware: Pipeline Execution and Error Handling

▼
Middleware functions intercept request and response cycles. Calling next() passes control forward; calling next(err) skips standard middleware directly to centralized error handlers with 4 parameters: (err, req, res, next).
